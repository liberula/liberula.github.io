id: T003
title: Create Supabase pending orders and Mercado Pago sandbox checkout
---

## Objective

Create a server-controlled pending order and initiate a Mercado Pago Checkout Pro sandbox payment for `R$ 79,90`.

Do not trust product identity, price, or payment state supplied by the browser.

## Context

T002 provides a validated buyer payload containing name, email, WhatsApp, and delivery address.

The repository is deployed on Cloudflare Pages and may use Pages Functions.

Supabase is available for persistence.

Mercado Pago Checkout Pro is the approved payment provider for this plan.

Required environment variables are expected to be configured outside the repository:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `MERCADO_PAGO_ACCESS_TOKEN`

Use sandbox or test credentials only.

## Expected delivery

Add:

- the minimal Supabase schema or migration needed for orders;
- a server-side order creation endpoint;
- a server-side Mercado Pago preference creation flow;
- return and cancellation URLs;
- safe redirection to Checkout Pro;
- a pending-order reference that T004 can reconcile.

## Scope

- Inspect existing Supabase conventions before adding schema.
- Add a migration for the minimum order data required by this plan.
- Store buyer name, email, WhatsApp, address, order status, amount, currency, case ID, timestamps, provider identifiers, and an idempotency key or equivalent.
- Create orders initially as `pending`.
- Define the product and `R$ 79,90` amount server-side.
- Create a Checkout Pro sandbox preference server-side.
- Associate the Mercado Pago external reference with the internal order.
- Configure success, pending, failure, and cancellation return URLs.
- Avoid duplicate orders caused by repeated clicks or retried requests.
- Return only the data required for redirecting the buyer.
- Add automated tests with Mercado Pago and Supabase calls mocked where practical.
- Add clear controlled errors when configuration is absent.

## Out of scope

- Production Mercado Pago credentials.
- Real payments.
- Webhook processing.
- Marking orders as paid.
- Post-purchase content.
- Magic-link authentication.
- Email sending.
- Admin dashboard.
- Shipping fees.
- Tax calculation.
- Final legal policy.
- Commit, push, deploy, or remote credential configuration.

## Implementation direction

Use server-side Cloudflare-compatible code.

Do not expose `SUPABASE_SERVICE_ROLE_KEY` or `MERCADO_PAGO_ACCESS_TOKEN` to the browser.

Do not accept amount, currency, product title, case ID, or success status from the client as authoritative.

Prefer a database constraint or idempotency strategy that prevents accidental duplicates.

Store structured address data when practical instead of a single unvalidated blob.

Use migrations committed to the repository rather than undocumented manual table creation.

Keep provider-specific logic isolated enough for testing.

## Definition of Done

- A migration defines the required order persistence.
- A valid buyer payload can create one pending order.
- The order amount is always `79.90` BRL as defined server-side.
- The case identifier is always `eco-sp-001` as defined server-side.
- Mercado Pago preference creation occurs server-side.
- The buyer can be redirected to the sandbox checkout.
- The preference contains an external reference linked to the internal order.
- Return URLs are configured.
- Repeated identical submission does not create uncontrolled duplicate orders.
- Invalid buyer payloads are rejected.
- Missing environment variables produce controlled errors.
- No service-role or Mercado Pago token appears in client assets.
- Tests mock external integrations.
- Existing tests pass.
- The production build succeeds.
- No real payment is attempted.
- No commit, push, or deploy is performed.

## Validation

Run the repository test suite.

Run the production build.

Apply the migration to a local or dedicated test Supabase environment.

With sandbox credentials configured:

- create a valid order;
- verify its `pending` state;
- verify amount and currency;
- verify buyer data;
- verify the provider external reference;
- open the sandbox checkout;
- cancel and retry;
- submit the same request repeatedly and inspect duplicate handling.

Inspect the generated client assets for leaked credentials.

## Manual test instructions

Configure test-only environment variables in the Cloudflare preview or local development environment.

Solve the case and complete the buyer form.

Start checkout.

Confirm that:

- Mercado Pago shows `R$ 79,90`;
- the order exists in Supabase;
- its state remains `pending`;
- cancelling returns to the expected site route;
- retrying does not create uncontrolled duplicate records.

Do not use production credentials.
