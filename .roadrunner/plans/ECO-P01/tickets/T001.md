## Objective

Create the first functional web entry point for Case `ECO-SP-001` at:

`/eco/eco-sp-001`

Allow the user to submit the case answer and validate it server-side without exposing the canonical answer in the public Next.js bundle.

## Context

The repository is deployed as a statically exported Next.js site on Cloudflare Pages.

Cloudflare Pages Functions may be used for server-side behavior.

The canonical answer is stored in the Cloudflare environment variable:

`ECO_SP_001_ANSWER`

Expected production value:

`Posto de Serviços Telefônica`

Answer comparison must ignore:

- uppercase and lowercase differences;
- accents and diacritics;
- leading and trailing whitespace;
- repeated internal whitespace.

Examples that must be accepted as equivalent:

- `Posto de Serviços Telefônica`
- `posto de servicos telefonica`
- `POSTO DE SERVIÇOS TELEFÔNICA`

## Expected delivery

Add the public case route, answer form, answer normalization logic, and a Cloudflare Pages Function endpoint that returns whether the submitted answer is correct.

Provide clear states for:

- initial;
- submitting;
- incorrect answer;
- network or server failure;
- correct answer.

The correct-answer state may be visually provisional.

## Scope

- Add `/eco/eco-sp-001`.
- Add an accessible text input and submit action.
- Add reusable answer normalization with automated tests.
- Add server-side answer comparison using `ECO_SP_001_ANSWER`.
- Add safe JSON responses.
- Add basic request validation.
- Prevent the canonical answer from being embedded in client-side code.
- Preserve the existing static export and Cloudflare Pages deployment.
- Keep the implementation usable on desktop and mobile.
- Add basic analytics events only through analytics systems already present in the repository.

## Out of scope

- Final visual identity.
- Commercial offer.
- Buyer data collection.
- Supabase.
- Mercado Pago.
- Payment status.
- Post-purchase content.
- Production secrets.
- Commit, push, deploy, or remote configuration changes.

## Implementation direction

Inspect the existing Next.js and Cloudflare Pages structure before adding files.

Prefer a small Pages Function endpoint such as:

`/api/eco/eco-sp-001/validate`

Do not add Supabase or another persistence layer.

Do not create a client-side fallback containing the canonical answer.

When `ECO_SP_001_ANSWER` is absent, return a controlled server error without revealing configuration details.

## Definition of Done

- `/eco/eco-sp-001` renders successfully.
- The route contains an accessible answer field and submit action.
- Correct answers are accepted regardless of case.
- Correct answers are accepted without accents.
- Leading, trailing, and repeated internal whitespace are ignored.
- Incorrect answers are rejected.
- Empty input is rejected without calling the API when practical.
- The canonical answer is not present in the public client bundle.
- Missing server configuration produces a controlled error.
- Loading, incorrect, correct, and failure states are implemented.
- Automated tests cover answer normalization.
- Existing tests continue to pass.
- The production build succeeds.
- No credentials or answer values are committed.
- No commit, push, or deploy is performed.

## Validation

Run the repository test suite.

Run the production build.

Test the validation endpoint with:

- exact answer;
- lowercase answer;
- uppercase answer;
- answer without accents;
- answer with repeated spaces;
- incorrect answer;
- empty input;
- missing environment variable.

Inspect the generated client assets and confirm that the canonical answer is absent.

## Manual test instructions

Configure `ECO_SP_001_ANSWER` only in the local or preview server environment.

Open:

`/eco/eco-sp-001`

Submit the accepted variations and confirm that all reach the correct-answer state.

Submit an incorrect answer and confirm that it remains on the mission page with a clear non-destructive error.

Simulate a failed request and confirm that retrying remains possible.

Check the page at common desktop and mobile viewport widths.
